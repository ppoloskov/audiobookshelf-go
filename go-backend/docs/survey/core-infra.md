## 2. REQUEST PIPELINE
- main passes the `Manager` to `http.Server` as its handler. `Manager.ServeHTTP` takes a mutex only to read `closed`, then calls `current.Load().ServeHTTP`. A nil runtime or closed manager gives 503 "server is restarting".
- `Runtime.ServeHTTP` (runtime.go:229):
  - Sets `Referrer-Policy`.
  - Sends any path equal to or under `/socket.io` or `<base>/socket.io` straight to the hub. These skip the panic guard because websocket upgrades need Hijacker.
  - Everything else goes through `guardPanics` (recover.go) and then `serveHTTP` (runtime.go:244).
- `serveHTTP`:
  - Strips the base path with `TrimPrefix`, so unprefixed paths also work.
  - Adds a CSP header unless `allowIframe` is set. This reads server settings on every request.
  - Handles `/ping`, `/healthcheck` and `/status` inline.
  - Calls `identity.Handle`, a hand-written switch over `METHOD path` for login, refresh, logout, init, openid and `/api/authorize`. It matches before any auth.
  - Non-`/api` paths try the mux with no user (feeds, shares, HLS, session tracks), then fall to the SPA/static handler.
  - `/api` paths are public only for GET item cover and author image (regex-free path split). All others call `identity.Authenticate`; failure gives plain-text 401 "Unauthorized".
  - `serveRoute` puts the user into the context, but only for authenticated requests. Routes are `mux.Handle("GET /api/...")` patterns registered by 170 call sites across feature packages. Non-canonical paths are mapped by `routeAlias`: one trailing slash is dropped, and `/api/collections//` and `/api/playlists//` are special-cased.
  - Unmatched `/api` gives `httputil.Fail` with 404 and an empty message. That is `SendStatus`, so the body is "Not Found" as text/plain with a weak ETag.
- `guardPanics` wraps the writer to track whether the response started. It logs a stack on panic and, if nothing was sent, writes Express's `<pre>Internal Server Error</pre>` HTML page. It also writes DEBUG access lines (TRACE for ping/healthcheck).
- Static client: `serveClient` serves a file, a directory index, or `index.html` for 21 hard-coded dynamic client routes compiled to regexes. Any other path gets the Express "Cannot GET /x" HTML 404.
- Manager/Runtime swap: a restore (manager.go:122) holds the manager mutex and does the following.
  - Validates the temp DB with `store.Open`.
  - Closes the old runtime and store.
  - Renames the old DB aside (to `.restore-previous`) and moves the new one in.
  - Stages the metadata `items/` and `authors/` dirs (copy, rename, with `.restore-previous` backups).
  - Opens a new store and builds a new `Runtime` that reuses the same `Hub`, so sockets survive.
  - On failure, rolls everything back and re-opens the old state. If that also fails, `current` becomes nil and every request gets 503.

## 3. DATA ACCESS TODAY
- There are four mechanisms:
  1. sqlc output: 112 queries from 8 `.sql` files, with 155 call sites in 10 packages.
  2. Raw SQL with a manual `Scan`: 391 `QueryContext/QueryRowContext/ExecContext` calls in non-test code, spread across about 75 files, plus about 267 `.Scan` sites.
  3. Dynamic SQL built from ordered slices, which `store.QueryIn` (500-item chunks) helps with.
  4. Small domain-specific loaders in `store` and in `progressdto`, `itemwrite`, `playlistview` and similar.
- Raw is about 2.5 times the sqlc call count.
- sqlc is configured with overrides in `sqlc.yaml`. Its input is a derived trigger-free, unquoted schema copy produced by a Makefile awk script, with a drift test against the pinned schema.
- Representation:
  - DATETIME is `any` in sqlc models and in raw scans. It is parsed by `dbtime.OptionalMillis/Millis/Time`, which accept 6 stored spellings (Sequelize text, RFC 3339, millis ints, `time.Time`). Writes use `dbtime.Format`, producing `"2006-01-02 15:04:05.000 -07:00"` in UTC.
  - JSON is `sql.NullString` or string. It is decoded by hand through `store.DecodeJSONSlice/Object` and `lenientJSON`. JSON is written as a string and never `[]byte`, because that binds as BLOB. `assertNoBlobText` guards this in tests.
  - Nullable columns are `sql.Null*` (591 references outside sqlc), with `NullStringPtr`, `NullIfEmpty` and similar converters.
  - Flags are TINYINT as `int64` or `NullInt64`.
- Schema has 26 tables and 306 columns:
  - apiKeys 11, authors 9, bookAuthors 4, bookSeries 5, books 23, collectionBooks 5, collections 6
  - customMetadataProviders 8, devices 11, feedEpisodes 18, feeds 22, libraries 12, libraryFolders 5, libraryItems 25
  - mediaItemShares 11, mediaProgresses 15, migrationsMeta 2, playbackSessions 22, playlistMediaItems 6, playlists 7
  - podcastEpisodes 19, podcasts 25, series 7, sessions 10, settings 4, users 14
  - It also has 27 indexes and 7 triggers.
- `store.validateSchema` checks only 6 tables' columns.
- `serversettings` is a document of `map[string]any`, cached per `*sql.DB` pointer in a `sync.Map` with a `Forget` hook. `Doc()` deep-copies by JSON round-trip. There are 389 `map[string]any` occurrences in non-test code, and the ratchet baseline counts 435 including aliases.

## 4. REALTIME
- Supports Engine.IO v4 over websocket only (`transport=websocket`, `EIO=4`). There is no polling and no upgrade, which matches the web client's `transports: ['websocket']`.
- Supports the default namespace only, with Socket.IO v4 packets: connect, disconnect, event with ack id, ack, and connect_error. Binary packets are rejected.
- Heartbeat is 25s ping / 20s timeout, with a 256-packet outbound buffer and a 5s write timeout. A full buffer drops the connection.
- Uses `golang.org/x/net/websocket`.
- Mounted at `/socket.io` and `<base>/socket.io`.
- File sizes: eio.go 239, sio.go 228, hub.go 397, socketauth.go 141, itemevents.go 84, covers.go 35.
- Addressing: `Emit(audience, event, payload)`.
  - `"*"` goes to all authenticated sockets, filtered per user for item payloads (typed `items.*` or maps carrying `libraryId`).
  - `"@admins"` goes to admin/root.
  - Any other string is treated as a user ID.
  - `EmitSocket(socketID, ...)` targets one socket.
- Client-to-server events handled: `auth`, `cancel_scan` (admin), `search_covers`, `cancel_cover_search`, `set_log_listener` (admin), `remove_log_listener` (unauthenticated, matching upstream), `message_all_users` (admin), `ping`, `disconnect`.
- The web client emits only auth, cancel_scan, set/remove_log_listener, search_covers and cancel_cover_search.
- Server-to-client events handled in this scope: `init`, `auth_failed`, `user_online`, `user_offline`, `log`, `admin_message`.
- The hub asks the `Backend` interface for the current runtime on every use, so a restore swap is invisible to it.

## 5. LOGGING
- Seven levels (TRACE..NOTE, numeric 0-6). Console format is `[YYYY-MM-DD HH:mm:ss.SSS] LEVEL: msg`, local time. TRACE/WARN/ERROR/FATAL go to stderr.
- Each entry is `{timestamp, source "file.go:123", message, levelName, level}`.
- Files:
  - `<metadata>/logs/daily/YYYY-MM-DD.txt` holds one JSON object per line, with HTML escaping off.
  - It keeps `loggerDailyLogsToKeep` files, default 7.
  - On load it rewrites the file without bad lines.
  - FATAL entries also go to `<metadata>/logs/crash_logs.txt`.
  - An empty `logs/scans` dir is created.
  - Entries logged before `OpenFiles` are buffered.
- In memory: a tail of the last 5,000 entries. `GET /api/logger-data` (admin) returns it as `{currentDailyLogs}`; `pages/config/log.vue` reads it.
- Socket listeners: `set_log_listener(level)` registers a socket. Entries at or above its level are emitted as `log` events, and FATAL always goes through.
- Level changes come from the `logLevel` setting, applied at boot, on settings PATCH and on restore. There is a package-level default logger used in 56 files; 212 call sites across non-test code, plus the `log` and `http.Server.ErrorLog` writers.
- A `log/slog` design needs:
  - A custom handler producing the console line and the JSON entry (the source file:line, which slog's `AddSource` supplies).
  - A daily-rotation file sink with a retention count.
  - A 5,000-entry ring buffer.
  - A fan-out to socket listeners.
  - A `slog.LevelVar` mapped from the 0-6 levels, with FATAL and NOTE as custom levels.
  - A crash-log file.

## 9. HAZARDS (must survive)
- One SQLite connection (`SetMaxOpenConns(1)`) means no query on the pool while a `Rows` or `Tx` is open. `dbnest` polices this today, so a typed transaction/cursor API is needed to keep the rule.
- DSN: `_pragma=busy_timeout(5000)` and `foreign_keys(1)`, with a check after open that `foreign_keys` is on.
- No journal-mode pragma is set. The file stays in rollback (DELETE) mode so TS v2.37.2 can reopen it. Do not switch to WAL. `removeSQLiteSidecars` only cleans up leftovers.
- DATETIME text format `"2006-01-02 15:04:05.000 -07:00"` in UTC, plus tolerant parsing of the 6 stored spellings. Never write BLOBs into TEXT or JSON columns, and keep NULL as NULL.
- Schema/migration check: `migrationsMeta` `version` and `maxVersion` must both equal `version.Server`, and the model columns must exist. Go refuses to open any other DB rather than migrate it.
- Fresh install: `bootstrap.Ensure` creates the file with `O_EXCL` (race-safe), applies the pinned schema in one transaction, inserts migration rows and default settings, and removes the file on failure. It never touches an existing DB.
- Shutdown: signal, then `srv.Shutdown` with a 10s timeout, then `manager.Close` (runtime handlers, then the hub, then the store), then the logger closes. The tests rely on the server stopping before the manager closes the DB.
- Socket auth ordering:
  - Handlers are attached before the client sees "40".
  - `auth` is the first event; the `lastSeen` DB write must complete before `init` is emitted.
  - Admins get `user_online` then `init` with `usersOnline`.
  - `remove_log_listener` needs no auth. Socket auth must use a context independent of the HTTP request.
  - `Hub.Refresh` fails closed for revoked or deactivated users.
- Other behaviours: panic means 500 with the Express page only if nothing was sent; `X-Forwarded-For` is the client IP; secrets (`tokenSecret`, openid fields) stay out of browser views; `JWT_SECRET_KEY`/`tokenSecret` persistence.
