## Queue and lifecycle negative space

- Podcast downloads are a separate background queue, not part of playback session downloads. `enqueue` deduplicates current/queued URLs, starts one and queues the rest (`go-backend/internal/podcasts/downloads.go:64-109`); completion marks task and emits `task_finished`, then `episode_download_finished`, then advances queue (`:182-227`). `Handler.Close` stops scheduler, cancels active download, drops waiting queue (`go-backend/internal/podcasts/podcasts.go:516-527`). `TestDownloadsRunOneAtATimeInQueueOrder`, `TestFailedDownloadIsReportedAndQueueContinues`, and `TestCloseCancelsRunningDownloadAndDropsQueue` cover order, retry-through-failure, cancellation, and idempotent close (`go-backend/internal/podcasts/lifecycle_test.go:182-221,261-328`). No actionable discrepancy established in this bounded pass.
- Audiotools encode/embed queue cancellation and shutdown have explicit route tests: cancellation (`go-backend/internal/audiotools/routes_test.go:158-193`), serial queue (`:210-245`), failure continuation (`:265-290`), close cancellation/drop queue (`:292-308`). No discrepancy promoted.
- HLS close marks transcode closed, cancels context, waits up to three seconds, then removes stream root (`go-backend/internal/playback/hls.go:269-285`); restart checks closed before launching (`:161-188`). Existing clean-close tests are listed above; no separate shutdown defect established.

## Resolved playback transitions

1. Local repeat upload now retains metadata and only updates the TS fields. The regression first failed because the Go upsert changed `Original metadata` to `Replacement metadata`.
2. HLS now checks the generated-segment frontier, resets at distance >10, recovers backward requests even after completion, waits for old ffmpeg exit, and preserves the full playlist. Initial far-forward regression failed with zero reset events.
3. Process startup now cleans orphan UUID stream folders while preserving non-UUID entries. The regression first failed because the orphan remained after `NewManager`.

## Final HLS review follow-up

The real 60-second AAC/FFmpeg/HTTP regression exposed an additional TS mismatch: Go-only final-playlist promotion replaced the full-duration `output.m3u8` with a suffix beginning at `output-2.ts`. Removing that promotion preserves the full public playlist after completion and backward reset; the test checks the public playlist still includes `output-0` and `output-9`. A separate zero-time guard now suppresses `stream_reset` when `at == 0`, matching TS's truthy event condition while restart polling still verifies progress. The real-media playlist regression passes. The new zero-event assertion has been race-sensitive; its observable-restart assertion is being stabilized and must pass the affected race run before N2 acceptance. G4 full playback/package tests passed before this last assertion adjustment; do not call the HLS race gate complete until the follow-up result arrives.
