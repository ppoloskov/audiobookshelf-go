## Ranked suspects / next regressions

1. **Missing-item scan bookkeeping (source-observed (pending independent reproduction), low):** Go's full scan omits TS bulk writes to missing item's `lastScan` and `lastScanVersion`. Add fields to existing missing transition test and decide whether watcher deletion intentionally differs (TS watcher path only saves item; do not globally alter `markMissing` without separating call paths).
2. **Missing→reappearance watcher lifecycle (coverage gap, medium):** existing tests cover each direction separately, not a full watcher round trip. Add an integration-style injected batch regression preserving item identity and clearing missing state.
3. **Directory walk errors can look like absence (hypothesis, medium):** Go continues after non-cancel walk failure then compares partial/empty set. Determine whether TS throws/rejects or returns partial/empty from `recurseFiles` on permission/I/O errors before labeling parity bug; add injectable walk failure test if Go should fail closed.
4. **Moved cover/ebook/audio file transition (coverage gap, low-medium):** code has explicit inode matching and cover path carry-forward; golden currently may primarily validate common audio move. Pin each media type and cover behavior if not covered.
5. **Missing `lastScan` on full-scan item transition (source-observed (pending independent reproduction), low):** can affect clients/admin UI reading per-item scan freshness while library scan advances. This is separate from no-op behavior: tests already verify repeated missing scans do not rewrite the row (`scanner_test.go:334-383`).
