## 1. API base
- Server address is stored as the full base URL (protocol + host + optional path prefix). JS: `ServerConnectForm.vue:668` (prepends `https://` if no protocol), `ServerConnectForm.vue:755` (strips trailing slash). The router base path is therefore carried inside `address`, not computed by the client.
- Paths are appended to `address` with no added `/api` prefix. Callers pass literal `/api/...` strings. Examples: JS `plugins/nativeHttp.js:19-21` (`url = serverConnectionConfig.address + url`), JS `plugins/axios.js:55-58` (same for `$axios`), AND `server/ApiHandler.kt:61-62` (`"${address}$endpoint"`), iOS `Shared/util/ApiClient.swift:32` (`"\(address)/\(endpoint)"` with endpoints written without a leading slash, e.g. `api/me`).
- Socket base: `plugins/server.js:30-32,39` splits `address` into host (`protocol//host`) and path (`pathname`), then uses `path: ${serverPath}/socket.io`, so a sub-path deployment is honored.
- CONFIRMED. The client does not reference any `/audiobookshelf` literal; the prefix only exists if the user typed it into the server address.

Notes on HTTP coverage:
- The JS web layer makes its API calls through `nativeHttp` (CapacitorHttp wrapper) at roughly 80 call sites (53 single-line `nativeHttp.<verb>(` matches plus 26 multi-line chained calls), and through `$axios` at 4 call sites (`EpubReader.vue:304`, `ComicReader.vue:246`, `MobiReader.vue:84`, `AbsAudioPlayer.js:78`) plus the interceptor in `plugins/axios.js`. `ServerConnectForm.vue` and `store/user.js` use CapacitorHttp directly for `/status`, `/ping`, `/login`, `/auth/openid*`, `/auth/refresh`.
- The native layers do not share the JS HTTP stack: Android uses OkHttp via `ApiHandler.kt` and `InternalDownloadManager.kt`; iOS uses Alamofire via `ApiClient.swift` and `URLSession` downloadTasks.
- `/api/me/progress` PATCH from Android goes to the active `DeviceManager.serverAddress` only (`ApiHandler.kt:95-98`), not to the config that owns the item.
