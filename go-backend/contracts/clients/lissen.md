## Auth

- Auth methods: `GET {host}/status` -> `authMethods` containing `local` (credentials) and/or `openid` (OIDC) (P/common/api/AudiobookshelfAuthService.kt:104-150; P/common/converter/AuthMethodResponseConverter.kt:30-46). CONFIRMED.
- Credentials login: `POST login` with JSON `{username, password}` and header `x-return-tokens: true` (P/common/client/AudiobookshelfApiClient.kt:201-205; P/common/api/AudiobookshelfAuthService.kt:58-102). Reads `user.token` (legacy token), `user.accessToken`, `user.refreshToken`, `user.username`, `userDefaultLibraryId` (P/common/model/user/LoggedUserResponse.kt:8,15; P/common/converter/LoginResponseConverter.kt:29-36). CONFIRMED.
- Persisting: `ChannelAuthService.persistCredentials` (app/src/main/kotlin/org/grakovne/lissen/channel/common/ChannelAuthService.kt:31-44) saves host and username, and each token only when non-null. Storage keys: `token`, `access_token`, `refresh_token` (app/src/main/kotlin/org/grakovne/lissen/persistence/preferences/SessionPreferences.kt:114-118), written through the encrypted secret store (SessionPreferences.kt `saveSecret`). CONFIRMED.
- How the token is sent: `Authorization: Bearer <accessToken ?: token>` added by an OkHttp application interceptor in `createOkHttpClient` (app/src/main/kotlin/org/grakovne/lissen/channel/common/OkHttpClient.kt:89-99). Every client built by that function gets it: the API client, the media (ExoPlayer) client (LissenDataSourceFactory.kt:37-45), the download client (the API client's OkHttp), the `/status` client and the OIDC clients. No `?token=` query parameter exists (NOT FOUND, see below). The app also sends custom headers and a User-Agent on every request (OkHttpClient.kt:104-113; app/src/main/kotlin/org/grakovne/lissen/channel/common/UserAgent.kt:3-7; P/common/api/RequestHeadersProvider.kt:8-20). CONFIRMED.
- Refresh flow:
  1. Triggered when a call returns HTTP 401 or 403 (`errorForCode`, P/common/api/SafeApiCall.kt:426-431). CONFIRMED.
  2. `executeWithRetry` (P/common/api/AudioBookShelfApiService.kt:48-69) records the access token used, calls `refreshToken` once, then retries the original call once (lines 59-65).
  3. `refreshToken` (AudioBookShelfApiService.kt:77-110) holds a mutex, skips if the stored access token already changed (79-82), reads the refresh token (84), and calls `POST auth/refresh` with `x-refresh-token` (AudiobookshelfApiClient.kt:207-211).
  4. On success it saves refreshToken and accessToken (AudioBookShelfApiService.kt:105-106). On a 401/403 from refresh it calls `session.clearCredentials()` (95-97), which logs the user out locally.
  CONFIRMED.
- API keys: NOT FOUND (see searched terms).
- OIDC / SSO flow (P/common/api/AudiobookshelfAuthService.kt:152-321):
  1. PKCE values: verifier = 42 random bytes as 84 hex characters; challenge = base64url(SHA-256(verifier)) without padding; state = 42 random bytes as hex (app/src/main/kotlin/org/grakovne/lissen/channel/common/Pkce.kt:9-31). CONFIRMED.
  2. Start: `GET {host}/auth/openid/` with the query shown in the HTTP table, redirect_uri `lissen://oauth` and client_id `lissen_app` (constants at P/common/oauth/OAuthScheme.kt:3-5). The 302 `Location` is opened in a Custom Tab. Cookies from the 302 are held in memory (`OAuthContextCache`, app/src/main/kotlin/org/grakovne/lissen/channel/common/OAuthContextCache.kt:6-34).
  3. Return: the app registers the `lissen://oauth` intent filter (app/src/main/AndroidManifest.xml:70-73). `AudiobookshelfOAuthCallbackActivity` (P/common/oauth/AudiobookshelfOAuthCallbackActivity.kt:53-64) checks the returned `state` against the stored one before exchanging. CONFIRMED.
  4. Exchange: `GET {host}/auth/openid/callback?state&code&code_verifier` with the stored Cookie header (AudiobookshelfAuthService.kt:259-277). The response body is parsed as LoggedUserResponse (300-305). CONFIRMED.
  5. Observations: (a) the PKCE `code_verifier` is sent in the callback URL query string, so it appears in URLs and any proxy or server access log that records them; (b) the callback request does not send `x-return-tokens: true`, unlike login and refresh, so the client depends on the server returning tokens in that response by default (INFERRED: server behaviour is outside this repo); (c) the PKCE and cookie store is an in-process singleton, so an OIDC round-trip does not survive process death (INFERRED impact).
- Logout: local only. `logout()` invalidates the conditional cache, clears the playing book, calls `preferencesReset.clearAll()` (which clears host, username, tokens and server version) and drops offline sessions (app/src/main/kotlin/org/grakovne/lissen/viewmodel/ConnectionSettingsViewModel.kt:131-139; app/src/main/kotlin/org/grakovne/lissen/persistence/preferences/PreferencesReset.kt:15-16). No server logout call exists (NOT FOUND).
- Observed risk (low): `persistCredentials` does not clear a stored token when the new response omits it (ChannelAuthService.kt:41-43). `getAccessToken() ?: getToken()` (OkHttpClient.kt:97) would then keep using a stale value. Logout clears everything before a new login (ConnectionSettingsViewModel.kt:134-136), which mitigates this in the normal flow.
- Observed (low): 403 is treated the same as 401 for refresh and for credential clearing (SafeApiCall.kt:428; AudioBookShelfApiService.kt:95-97). A refresh that returns 403 clears credentials.

## Caching and covers

### HTTP caching (OkHttp and the custom ETag store)

1. No OkHttp `Cache` is configured. The builder in `createOkHttpClient` (app/src/main/kotlin/org/grakovne/lissen/channel/common/OkHttpClient.kt:57-82) never calls `.cache(...)`. The only `.cache(` in app code is a Compose modifier unrelated to HTTP (app/src/main/kotlin/org/grakovne/lissen/ui/screens/player/composable/NavigationBarComposable.kt:250). Cache-Control, Expires and Last-Modified are not read anywhere (NOT FOUND). CONFIRMED.
2. Custom ETag store. `ConditionalCache` (P/common/api/ConditionalCache.kt:204-244) is an in-memory `LruCache` with `DEFAULT_MAX_ENTRIES = 32` (line 242). It is not persisted. Each entry holds the response object and its ETag together (`Entry`, lines 234-237), so a value and its validator are always read as a pair.
3. Key: `conditionalCacheKey` (ConditionalCache.kt:195-200) = `"<Java method name> <full URL including query>"`. The method name separates two endpoints that share a URL but return different types (book and podcast both use `api/items/{id}`). Requests without a Retrofit Invocation tag fall back to the URL.
4. Request side: `ConditionalCacheInterceptor` (P/common/api/ConditionalCacheInterceptor.kt:252-266) adds `If-None-Match` only when the request carries the `Cacheable` tag and the cache has an ETag for the key. It is attached only to the API client (P/common/api/AudioBookShelfApiService.kt:153). It is not attached to the media client, and the auth client creates its own `ConditionalCache()` with no interceptor (P/common/api/AudiobookshelfAuthService.kt:90). The download client is the API client's OkHttp (AudiobookshelfChannel.kt:58), so downloads pass through the interceptor, but their requests are untagged, so it does nothing for them.
5. Response side (`safeApiCall`, P/common/api/SafeApiCall.kt:345-382; `mapResponse` 384-417):
   - 304 -> returns the cached object for that key (`mapResponse`, lines 390-395). If there is no entry, it returns InternalError.
   - 200 with a body and an `ETag` header on a Cacheable request -> stores value and ETag (lines 401-405). A 200 without an ETag does not store and does not clear an older entry (line 404). This is safe: an old entry is used only when the server answers 304 to its own ETag.
   - Eviction race: if a 304 arrives and the entry was evicted in between (`evicted`, line 357), the call is repeated once without a validator (line 358).
   - Non-2xx other than 304 maps 401/403 to Unauthorized, 404 to NotFoundError, others to InternalError (SafeApiCall.kt:426-431). IOException maps to NetworkError (line 372-374).
6. Cacheable endpoints (12): fetchLibraries (AudiobookshelfApiClient.kt:48), fetchLibrary (:55), fetchUserState (:73), fetchLibraryItems (:98, book list), fetchPodcastItems (:109), fetchLibraryAuthors (:119), fetchLibraryStats (:125), fetchLibraryNarrators (:131), fetchLibraryPlaylists (:137), fetchLibraryItem (:157), fetchPodcastEpisode (:163), fetchAuthorLibraryItems (:169). All other endpoints are not revalidated. This includes login, refresh, personalized feed, progress, sync, batch get, search, play, bookmarks, and all covers and images. CONFIRMED.
7. Invalidation: `conditionalCache.invalidateAll()` runs after a login (app/src/main/kotlin/org/grakovne/lissen/content/LissenMediaProvider.kt:456) and on logout (ConnectionSettingsViewModel.kt:134). There is no time-based expiry and no invalidation after writes (bookmark create/delete, progress sync). Freshness after writes depends on the server changing its ETag, which it does for a content-hash ETag (INFERRED).
8. Server ETag: the client assumes the server sends an `ETag` on these JSON responses. Express-style servers do this by default (INFERRED; the server is outside this repo). If the server sends none, the store stays empty and every Cacheable request is a full fetch.
9. Auth scoping: a 304 is only returned by the server after it authenticates the request, and the ETag is a content hash, so a cached object cannot cross users unless the content is identical (INFERRED from server behaviour). Keys include the host, so internal and external hosts do not share entries.
