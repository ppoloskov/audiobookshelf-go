## HTTP calls

All JSON requests go through `API/Sources/API/NetworkService.swift` (`send`, 181-208; `performRequest`, 215-308; `buildURLRequest`, 310-354). Base URL is the user-entered server URL (+ optional subdirectory), path is appended with `URL.appendingPathComponent` (NetworkService.swift:321). `/api/` is a literal prefix on every API path. Non-API paths used: `/login`, `/auth/*`, `/status`, `/public/session/*`. Headers on every request: `Content-Type: application/json` (333), `Authorization: Bearer <token>` (Audiobookshelf.swift:51-58, see Auth), user custom headers (NetworkService.swift:335-343). Request bodies are JSON-encoded with `JSONEncoder` (349-351). Response dates are epoch milliseconds (NetworkService.swift:151-159).

## Auth

- Base URL and router base path: user enters host (scheme defaults to serverScheme) and optionally a subdirectory which is appended to the URL (AudioBooth/AudioBooth/Screens/Servers/Server/ServerViewModel.swift:543-562, subdirectory append 553-561). Nothing in code hard-codes "/audiobookshelf". Paths keep the literal "/api/..." prefix (NetworkService.swift:321). Media URLs use the same base (Book.swift:25, Session.swift:14-16).
- Login (username/password): POST /login with x-return-tokens: true (AuthenticationService.swift:80-81, 84). Response user.accessToken + user.refreshToken if present (with JWT exp), else user.token (legacy). Credentials enum in API/Sources/API/Models/Connection.swift:77-92: .bearer(accessToken, refreshToken, expiresAt, legacyToken), .legacy(token), .apiKey(key). User.credentials prefers access/refresh, falls back to legacy (User.swift:13-21).
- How the token is sent on API calls: `Authorization: Bearer <accessToken | legacy token | apiKey>` (Connection.swift:82-91; set in Audiobookshelf.swift:51-58 via `headersProvider`, and in AuthenticationService.swift:208, 451; LibrariesService.swift:111; DownloadManager.swift:1328). No query-string token on API calls. Query-string token IS used for media URLs (see "token=" rows above).
- Refresh flow: CredentialsActor.swift:14-68. Every request calls `freshToken` (Audiobookshelf.swift:53). Refresh when access token expires within 60 s (CredentialsActor.swift:31-35) or is expired. Refresh = POST /auth/refresh with header x-refresh-token (AuthenticationService.swift:527-531) and returns new accessToken/refreshToken (538-550). Deduplicated through `refreshTask` (CredentialsActor.swift:22-24, 49-61). On 401 response with a refresh token present, the app marks the access token expired and sets status connectionError, but does not retry the failed request (NetworkService.swift:239-243; Server.swift:190-200). Refresh failure with 401/403: fall back to legacy token if present (CredentialsActor.swift:78-82), else clear credentials and set authenticationError (83-86). Other refresh failures: exponential backoff, capped at 60 s (90-93).
- Header closure fallback: if freshToken throws, the request goes out with no Authorization header (Audiobookshelf.swift:53-54).
- Logout: local only. AuthenticationService.swift:321-328 removes the connection from Keychain and clears caches. No server call (see Not found).
- API key: POST /api/authorize with `Authorization: Bearer <apiKey>` (AuthenticationService.swift:439-470; token 449; header 451). Stored as .apiKey (never refreshed; refreshToken(for:) returns it unchanged, AuthenticationService.swift:509-511). UI link to <server>/config/api-keys/ (AudioBooth/AudioBooth/Screens/Servers/Authentication/AuthenticationView.swift:104).
- OIDC: OIDCAuthenticationManager.swift. Steps:
  1. PKCE: 32 random bytes, base64url verifier, S256 challenge (201-224).
  2. Initial GET {base}/auth/openid with client_id=AudioBooth, response_type=code, scope=openid, redirect_uri=audiobooth://oauth, callback=audiobooth://oauth, code_challenge, code_challenge_method=S256 (106-124), custom headers attached (147). Expects 302; captures Location and cookies (167-181). 400 "Invalid redirect_uri" is mapped to a user hint (182-188; error text 238).
  3. ASWebAuthenticationSession with callback scheme "audiobooth" (31-37 on iOS 17.4+ with additionalHeaderFields = custom headers; 39-43 older). Callback query parsed for code, state, error (57-86).
  4. GET {base}/auth/openid/callback?code=&code_verifier=&state= with Cookie header rebuilt from the captured cookies and x-return-tokens: true (AuthenticationService.swift:126-151).
