## Scope
`internal/podcasts` and `internal/providers` contained handlers and unit tests but were never constructed/dispatched by `internal/server/runtime.go`, so 23 route candidates returned the explicit 501 fallback. Wire both into the runtime graph: construct, quick-match wiring, dispatch order after audiotools. Non-goals: no behaviour change inside the packages; differential variant verification is TASK-0007.

## Contract
Upstream dispatch semantics preserved: podcast routes under `/api/podcasts*` (feed create/checknew/downloads/clear-queue/search-episode/download-episodes/match-episodes/episode CRUD/OPML) and provider routes under `/api/search*`, `/api/custom-metadata-providers*` become reachable; admin/permission checks stay inside the packages (providers `isAdminOrUp` matches upstream `CustomMetadataProviderController.middleware`). Startup failure from `providers.New` must cleanly close previously created components.

## Architecture review
No new packages or dependencies: both packages already existed with tests. Alternatives: mount via sub-router package (unwarranted). New cross-package edges: server→podcasts, server→providers, podcasts→scanner callback (pre-designed SetQuickMatchHandler avoids an import cycle).

## Decisions
- Dispatch order places podcasts/providers after audiotools with no prefix overlap, mirroring no-conflict upstream route tree.
- Runtime error path closes scanner + hub when provider construction fails to avoid goroutine leaks.
