## Scope
Implement ROADMAP Phase 2's book serialization pilot: introduce typed `wire` book shapes, add a typed row loader/builders while retaining the existing serializer for dual-run, characterize source output for fixture and specified edge books, switch the item serialization path without changing observable JSON, then remove obsolete book-map helpers and lower the `map[string]any` ratchet. Expected Go scope is `internal/catalog`, `internal/wire`, and direct `ItemJSON`/`ItemMinifiedJSON` consumers in `userapi`, `scanner`, and the runtime item emitter as needed. No upstream behavior, unrelated DTOs, or non-book serializers are in scope.

## Contract
Pinned upstream v2.37.2 is the oracle. Preserve the three distinct book wire shapes (legacy full, minified, expanded), field names/order and null/empty/absent behavior. Keep nested audio-file, chapter, ebook, and track objects opaque as required by Architecture D5. Preserve existing `ItemJSON` and `ItemMinifiedJSON` use in API responses, scanner emits, and runtime hooks. No state transition applies to this read-only serialization; malformed/null stored JSON behavior must remain source-compatible and be tested where the fixture permits.

## Architecture review
`internal/wire` does not exist yet. A new package is explicitly required by this phase and is the smallest shared location for public book wire shapes used across catalog/API/scanner output. Keep structs limited to the book envelopes; retain `json.RawMessage` for inner pass-through objects. Avoid a generic serializer framework, added dependencies, or a new abstraction around SQLite. Existing consumers of `items.Reader` and emitted payloads must be inspected before changing concrete nested values.

## Decisions
No compatibility exceptions or owner decisions introduced. Medium risk reflects a new cross-package wire boundary and broad serializer consumers; use source-derived goldens and the existing differential gate.
