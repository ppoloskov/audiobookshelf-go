# Behaviour contract (migration / compatibility-critical work)

- Source repository/revision: upstream `advplyr/audiobookshelf`, release v2.37.2, baseline commit `edb1f7efc92ecacdef51aafb4d9d5054ce10604f` in this repository (`server/`, `index.js`, `client/`). The TypeScript sources in this repo are the reference; they must not be modified.
- Replacement end state: standalone pure-Go server binary (`go-backend/cmd/audiobookshelf-go`), `CGO_ENABLED=0`, no Node runtime in the replacement path. SQLite via `modernc.org/sqlite`; FFmpeg/ffprobe as external subprocesses where upstream requires them.
- Parity unit: one HTTP request/response (method+path+query+body, status, headers, JSON body shape/types, ordering), one Socket.IO protocol exchange, one persisted database/filesystem transition, one background job lifecycle.
- Known client and protocol consumers: the retained original web client (`client/`), mobile clients, ereader/auth flows, Socket.IO clients on both legacy and prefixed Engine.IO paths.
- Explicitly acceptable differences: NONE unapproved. Candidate acceptable differences must be recorded per capability with an owner-approved exception. Non-observable differences (raw SQLite page layout, index internals, log file wording, goroutine scheduling order that does not change emitted event order) are not compatibility surfaces.
- Incompatible differences requiring approval: response status/body/headers, error text and error status codes, null-vs-absent JSON fields, ordering, persisted schema/IDs values, metadata file effects, socket event payload/order/recipients, cookie/token semantics, configured `RouterBasePath` prefixing.
- Differential corpus and reproducible seed/state: `go-backend/contracts/parity/differential-cases.json` (case registry), fixture creation via `go-backend/tools/parity/create-fixture.cjs`, upstream-created `schema.sql` from a real fresh init, library golden from source-executed serializers. Node and Go servers are always started on independent copies of config, database, metadata AND media trees. Never two servers on one writable tree and never a live user database.
- Denominator and inventory reconciliation: `go-backend/contracts/source-inventory.json` generated by `go-backend/tools/source_inventory.py`; per-candidate state in `go-backend/contracts/parity/route-coverage.json`; flattened per-capability records in `docs/agent-work/capabilities/`. The retired ledger generator is preserved under `docs/agent-work/archive/parity-tools/`. Route candidates are syntax-level denominators; runtime-resolved routes may differ and must be reconciled during verification.
- Migration, cut-over and recovery plan: Go server replaces upstream for the pinned version only. Original instruction: never migrate implicitly; existing databases had to match the pinned migration version exactly. **Owner direction 2026-10-30 lifts the existing-database deferment**: compatibility with an existing v2.37.2 database (including partial upgrade states within the pinned release) is now in scope and must be verified for rollback — the pinned Node server must reopen Go-written databases. Rollback proof is a standing gate. Ebook support is an owner-approved compatibility stub (group/handle ebook files safely; no ebook engine).
- Decisions/approved exclusions: historical schema upgrade/migration support is deferred by user instruction (fail clearly instead of migrating). NUSQLITE3 full-text-search parity requires Go-side equivalent semantics before any parity claim (see ROADMAP). No exclusions of in-scope features without a recorded approved exception.

Historical provenance: work before 2026-10-29 predates the installed go skill pack ledger format; its evidence lives in `go-backend/contracts/parity/*` reports, `go-backend/VALIDATION.md`, `go-backend/HANDOFF.md`, `go-backend/STATUS.md` and `git` history of the packaged archive. Task ledgers created 2026-10-29 pin skill pack version 1.1.0 (files under `~/.agents/skills/*/VERSION`). Older work is not retroactively assigned a version; it is referenced as an inherited baseline.

No agent may reinterpret the contract solely to turn a failing differential test green. Source behaviour is characterized first; independent approved fixes may be separate changes.
