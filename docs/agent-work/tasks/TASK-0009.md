## Evidence
- Initial reading (2026-10-29): `internal/catalog/writes.go` item PATCH is transactional (BeginTx/Commit) and the post-commit emit at writes.go:151-155 skips emitting when the expanded `ItemJSON` serialization fails while still answering 200 with the non-expanded item.

- Upstream characterization (2026-10-29, `server/controllers/LibraryItemController.js updateMedia`, PATCH `/api/items/:id/media`):
  1. Upstream performs sequential writes with NO enclosing transaction: `media.updateFromRequest` (media save), `updateSeriesFromRequest`, `updateAuthorsFromRequest`, `checkRemoveEmptySeries`/`checkRemoveAuthorsWithNoBooks`, `libraryItem.save()`, `saveMetadataFile()`. A failure mid-sequence leaves partial application upstream. Go's single-transaction PATCH is therefore MORE atomic than upstream on failure paths; this is a benign difference direction (Go never worse: never partially applies). Verdict needed only if evidence shows a flow depending on partial application (unlikely). To be confirmed in differential runs (which normally only exercise success paths).
  2. Upstream emit ordering: `SocketAuthority.libraryItemEmitter('item_updated', req.libraryItem)` fires BEFORE `res.json({updated, libraryItem: req.libraryItem.toOldJSON()})`. The socket payload is the saved Sequelize model serialized by the emitter wrapper (expansion per recipient), not a re-read. Go emits AFTER writing the response using a fresh expanded re-read, and omits the emit entirely if that re-read fails. Two potential divergences to test in TASK-0007: (a) socket-event-before-response ordering; (b) emit omission on serialization failure and payload shape (`toOldJSON` vs Go expanded map).
  3. The HANDOFF "narrator updates can partially apply" item is not explained by this flow (Go narrators column update is inside the transaction); suspects are the podcast episode PATCH (file go-backend/internal/podcasts, under review by TASK-0006's workspace owner this session) and audiotools sequential metadata embeds; characterization deferred until those packages are free.
