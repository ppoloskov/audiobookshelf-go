## Scope
Upstream `server/Server.js` (default Nuxt-client branch, no `REACT_CLIENT_PATH`) registers: `express.static(client/dist)`, then an enumerated list of ~17 dynamic client routes (`/item/:id`, `/author/:id`, `/audiobook/:id/*`, `/library/:library*`, `/config/users/:id(/sessions)`, `/config/item-metadata-utils/:id`, `/collection/:id`, `/playlist/:id`, `/share/:slug`) each serving `client/dist/index.html`; anything else falls through to Express default 404. The `router.all('*')` catch-all exists ONLY in the Next.js client branch (`REACT_CLIENT_PATH` env). Go `internal/server/runtime.go serveClient` currently serves `index.html` for ANY unknown GET/HEAD path — a divergence for arbitrary unknown paths (upstream 404 vs Go 200+index.html).

## Contract
Unknown GET paths must 404 like upstream default config; the enumerated dynamic routes serve index.html; static assets take precedence; HEAD parity. The Next.js branch is env-conditional and can be documented as out-of-scope if the replacement pins the default client.

## Acceptance criteria
- [x] `serveClient` restricted to assets + enumerated dynamic-route list + 404 fallback (with express.static directory-index semantics).
- [x] Regression test `TestServeClientDynamicRoutesAndUnknownPath404` covers assets, root index, dynamic routes (incl. optional `:id?` and trailing slash), HEAD, unknown 404s and non-GET.

## Architecture review
Small change in `internal/server/runtime.go` plus package-level precompiled patterns; no new packages/dependencies. Alternative reverse-proxy matcher rejected as unnecessary.

## Decisions
- Upstream non-strict Express routing tolerates one trailing slash on dynamic routes; matcher regexes end with `\/?$` to match. Double slashes still unmatched, matching path-to-regexp segment semantics.
- The Next.js client branch (`REACT_CLIENT_PATH`) catch-all remains documented-only: the replacement pins the default client distribution, consistent with runtime serveClient's behavior for the retained `client/dist`.
