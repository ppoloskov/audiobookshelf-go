## Scope
Three defects found by characterization during differential verification:
1. `POST /api/collections` deadlocked the request permanently: `collectionDTO` ran `canAccessItem`/`ItemJSON` queries *inside* an open `rows` cursor while `store.OpenReadWrite` pins `SetMaxOpenConns(1)` — the nested `DB.conn` call waits forever for the only pooled connection (captured in a SIGQUIT goroutine dump: `canAccessItem → database/sql.DB.conn [select]` with an `Rows.awaitDone` goroutine parked).
2. `collectionBooks` queries used the unquoted SQLite keyword `order` (`INSERT ... (id,collectionId,bookId,order,createdAt)` and `ORDER BY cb.order`) — hard syntax error, producing the 500 seen in the first sanitized report.
3. User CRUD validation errors were emitted as `text/plain` with `http.Error` while upstream serves `res.send('...')` as `text/html; charset=utf-8` without a trailing newline (verified live against the reference server).

Fix (1)+(2)+(3) in `internal/userapi/userapi.go` + helper `sendText`; materialize item IDs before per-item queries.

## Contract
Behavior-preserving fixes only: same success payloads, upstream-matching status/content-type/body bytes for the converted validation errors. No test changes beyond new regression coverage. The remaining `http.Error` calls (500 "database read/write failed" paths without an exact upstream counterpart) are intentionally left as-is and recorded.

## Architecture review
No new package/dependency. Rows materialization is the smallest fix consistent with the deliberate single-connection pool (which preserves upstream's serialization semantics); alternatives (raising MaxOpenConns, changing journal mode) alter storage semantics and were rejected.

## Decisions
- A store-wide audit of the same rows-inside-loop pattern in other packages is dispatched as a separate owned task (see TASK-0012) to avoid overlapping file ownership.
- User CRUD messages converted are exactly those upstream serves via `res.send('...')`: "Username and password are required", "Invalid account type", "Username already taken", "Invalid email", "Invalid username", "Invalid permissions" (+ equivalents), 10 sites.
