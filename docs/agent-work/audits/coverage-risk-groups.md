## Ranked risk groups and representative case budgets

Counts below are planning estimates of **differential scenarios**, not existing records or claims of passing evidence. Per operation group, a normal + error + edge minimum is required; state-changing groups also require initial/repeat/changed/failure and force only where the API defines it. This matches the source-backed contract rule that success, malformed/missing/restricted cases, logical DB state and rollback must be checked (`go-backend/ROADMAP.md:7-9,46-55`).

1. **DB + filesystem + events / destructive cascade (very high): 30–45 cases.** Cover backup create/apply/upload/delete; catalog/item/library delete cascades; scan and batch collection/playlist writes; podcast download lifecycle. Minimum per operation: success baseline; missing entity; permission denial; malformed/empty input; injected DB or filesystem failure; verify response, DB logical state, file tree, event recipients/order, repeat/restart. Scan additionally initial/repeat/changed/force/failure; batch additionally empty, duplicate, mixed valid/invalid and ordering. Restore additionally Node reopen of the Go-written/restored database. Rationale: roadmap mandates DB/filesystem/error/event and rollback checks (`ROADMAP.md:7,22,53-55`); catalog deletion is coupled to relation cleanup and series events (`server/routers/ApiRouter.js:383-461`; Go `internal/catalog/writes.go:339-383`).
2. **Permissions, ownership and identity transitions (very high): 28–40 cases.** User create/update/delete, API-key create/update/delete, login/refresh/logout, email settings/device/send. Matrix: root/admin, owner, ordinary user, restricted libraries, no token, wrong token, inactive user; entity owner vs non-owner; all/none/partial tags including mixed-tag witness; valid/invalid/empty permissions; token/session before and after revoke/rotate; repeated mutation. B6's email tag allowlist and explicit podcast gates are specifically identified as high-risk and still lack targeted HTTP differential evidence (`audits/B6-acl.md:21-30,42-47`; task `TASK-20261030.md:62`).
3. **Rollback-safety-critical persistence / B5 (very high): 12–20 cases.** For each persisted write family (progress/session, podcast lifecycle, userapi collection/playlist, catalog metadata), write one record, compare raw SQLite values and logical state, restart, then have pinned Node reopen and read it. Include UTC millisecond boundaries, null/absent preservation, repeated update ordering and injected transaction failure. B5 found multiple timestamp encodings and lexical-order consumers (`audits/B5-datetime.md:11,38,99-103`); the session row evidence gap is acknowledged (`TASK-20261030.md:59,76`). Keep B5 database-format verification distinct from HTTP response equality.
