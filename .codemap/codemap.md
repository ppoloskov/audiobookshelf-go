## Cross-cutting themes

- **Copy-paste duplication is the dominant theme in both stacks.** Sibling files/packages keep near-verbatim copies that have already drifted: TS tag-vs-genre CRUD (~200 lines, MiscController 341-552), the book/podcast mirror query files (permission SQL + 5x json_each blocks), Database.js filterData methods x15, PodcastScanner.saveMetadataFile vs BookScanner; Go forks internal/ids.New (sharing uuid()), reimplements the Express weak-ETag writer in backup after identity owns it, and duplicates admin()/parseUA()/permission-merge across userapi/playback/emailapi/notifications/audiotools. Most repeated tag: duplication (17 modules).
- **Silent error swallowing on mutating and I/O paths.** The Go side's `_ =` pattern hides failures that change behavior: userapi's collection reorder commits a partially reordered list (tx errors ignored), playback swallows ffmpeg death and library-settings failures, adminops upload returns 200 on a partial disk write and zero stats on DB failure, scanner hides whole sidecar/cleanup breakage; TS MiscController.handleUpload returns 200 even if every file move failed; podcastUtils has a bare catch{ return '' }.
- **Legacy old-model vocabulary and dual-format payloads are live in both generations.** TS: pervasive toOldJSON*/toOldJSONForBrowser shims across all 25 models, media progress keyed by extraData.libraryItemId instead of mediaItemId, old mobile-client payload shims in PlaybackSessionManager, UserController accepting permissions in two shapes, deprecated-but-wired endpoints. Go: dual-payload accepts for upstream parity (podcastMetadataObject feedUrl/feedURL etc., read-only handler accepting authActiveAuthMethods as []any OR []string). This is the project's central migration risk: the Go rewrite targets the same wire quirks the TS side keeps alive.
- **Real correctness bugs found by reading against the upstream oracle.** ts_providers GoogleBooks destructures publisherDate instead of publishedDate so publishedYear is ALWAYS null (HIGH); MusicBrainz drops its required User-Agent via axios arg misuse; BookFinder.findCovers passes options in the isbn slot; CronManager guard leak permanently disables a podcast's downloads after any throw; g_comms audiotools labels every ffmpeg failure 'canceled by user' and never emits per-track progress; g_userapi claims /users/* routes then returns empty 200s. Each is concrete and testable.
- **Unbounded in-memory state accumulates without bound.** g_identity's rate limiter keyed by raw X-Forwarded-For never prunes (an unauthenticated attacker can exhaust memory on /login); sharing's pre-auth share-sessions map, playback's localIDs map, TS oldPlaybackSessionMap, ApiCacheManager's re-hooking on every backup restore, and profiler histogram values all grow without bound.
- **Hand-rolled routing is tracked debt, not an accident, in the Go rewrite.** All 13 feature packages dispatch via Handle(...) bool prefix matching, which go-backend/AGENTS.md now forbids; the runtime special-cases /api/tasks inline on top of the chain. It is ratchet-baselined legacy pending Phase 5 (ServeMux strangler) — but every new route deepens the deviation, and TS carries its own analogue: ApiRouter doubling as a service object holding business logic that Scanner calls back into.
- **God-files sit exactly at the dispatch/seam points.** server/Database.js (1004 lines: DDL authoring + filter-cache CRUD + cleanup policy + version patching), internal/catalog/handler.go (2807), internal/userapi/userapi.go (2535), server/Server.js start() (~230 lines), MiscController (grab-bag of 17 endpoints), sharing/handler.go (1405). Decomposition elsewhere proves the rule fits; the dispatch sinks accrete instead.
